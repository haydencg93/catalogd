# Catalogd: Settings Page Documentation

The Settings page provides a comprehensive dashboard for users to manage their public profile, streaming preferences, privacy constraints, and account security, while also functioning as a powerful data migration hub capable of executing complex bulk imports and exports.

## User Profile & Preferences Management

When `initSettings()` executes, it fetches the active user's data from the `profiles` table to pre-fill the form inputs.

* **Public Profile:** Users can configure their display name, bio, and social media handles (which are parsed into the `socials` JSON object). The page generates a custom shareable link to their profile, copying it to the clipboard upon clicking the link icon (🔗).


* **Favorites Manager:** Users can establish their "Top 5" favorite items across five categories (Movies, TV, Books, Music, YouTube). Clicking "Search to add Favorite" triggers `setupFavoritesSearch()`, querying external APIs and rendering a dropdown of results. To manage the order, `Sortable.js` is instantiated on the favorites containers, allowing users to drag and drop items; this visually updates their `#1` through `#5` rankings and mutates the `currentFavs` object accordingly. The `#1` item from each category is automatically extracted to construct the "Top 5 All" list via `updateTopAll()`.


* **Streaming & Language Preferences:** Users can select the streaming services they subscribe to by clicking visual `.pill` elements. The `fetchAndRenderProviders()` function queries the TMDB API for US watch providers and filters them into two distinct arrays: "Streaming" (SVOD) and "Buying & Renting" (TVOD), rendering them into separate grid containers. These selections dictate the availability filters applied in the "For You" and "Random Decider" engines.


* **Privacy Controls:** A series of checkboxes allow users to toggle the visibility of their Active Status, Paused/Dropped logs, Fandoms, and Tracked People on their public profile.



Clicking "Update Profile" aggregates all input values and executes an `update` against the `profiles` table.

## Security & Account Lifecycle

* **Credential Updates:** Users can request an email change by verifying their current password via `signInWithPassword()` before executing `updateUser({ email: newEmail })`. A similar flow facilitates password updates.


* **Account Deletion:** Located in the `.danger-zone`, users can permanently delete their account. Upon password verification, the client invokes a custom Supabase Remote Procedure Call (`delete_user_account`) to bypass cascading constraints safely before signing the user out.



## Bulk Export Pipeline

The Export engine bundles a user's entire account history into a structured `.zip` file using the `JSZip` library.

1. **Scope Definition:** The user selects a date range (e.g., "All Time" vs. "Last 7 Days") and a media filter (e.g., "Movies Only").


2. **Data Fetching:** The `startFullAccountExport()` pipeline systematically queries the `profiles`, `media_logs` (Diary), `user_watchlist`, `media_status`, `media_lists`, and `custom_imgs` tables.


3. **Data Formatting:** The JSON responses are passed through `Papa.unparse()` to convert them into structured CSV strings, injecting headers that mimic the "Letterboxd" standard export format (e.g., `tmdbID`, `WatchedDate`).


4. **Zip Generation:** The script organizes the CSV files into a folder hierarchy (e.g., `/Account/Settings`, `/Movies/Diary.csv`) and generates a Blob download. An interactive UI progress bar calculates completion percentage linearly based on the operational step.



## Bulk Import Pipeline

The Import engine ingests standard CSV formats (like those generated by Letterboxd) and reconstructs the data inside Catalogd. It utilizes `PapaParse` to convert the uploaded file into an array of JSON objects.

1. **Media Resolution:** Because imported CSVs rarely contain universal TMDB/OpenLibrary IDs, the `resolveMedia(title, year)` function queries the external TMDB search endpoints using the text string. It grabs the first result, subsequently fetching its full details to extract the `runtime`.


2. **Sequential Upserting:** The script iterates through the parsed rows sequentially. To respect TMDB rate limits, `await new Promise(r => setTimeout(r, 200))` forces the loop to pause briefly between each iteration.


3. **Conflict Handling:** For standard Diary imports, if a log already exists for that media on that date, the script checks the `shouldOverwrite` toggle. If checked, it appends the existing row's ID to the payload, forcing Supabase to execute an `update` instead of an `insert`.


4. **Specialty Importers:** Dedicated handlers process list imports (`processListData`) by creating a new `media_lists` row and attaching items, while Last.fm integration (`start-lastfm-sync-btn`) pulls the user's top/recent scrobbles directly from the Last.fm API, rendering an interactive modal (`#bulk-log-modal`) where users can rate the imported tracks before saving them.
